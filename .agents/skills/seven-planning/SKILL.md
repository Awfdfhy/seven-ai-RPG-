# Seven Planning
Trigger: new feature, broad bug, roadmap work, multi-file change, or uncertain scope.
1. Read the product contract and current status; distinguish verified facts from assumptions.
2. Define user outcome, non-goals, constraints, dependencies, files likely affected, and risks.
3. Split work into small independently verifiable tasks. Every task has a testable acceptance criterion.
4. Prioritize blockers and data/security risks before polish.
5. Record decisions and evidence in the existing project planning format; avoid duplicate competing plans.
6. Do not mark a task complete until the acceptance criterion and evidence are recorded.
