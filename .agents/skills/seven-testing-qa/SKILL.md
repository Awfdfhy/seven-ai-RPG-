# Seven Testing QA
1. Map each acceptance criterion to at least one test or explicitly documented manual check.
2. Cover success, failure, boundary, persistence/reopen, and compatibility cases.
3. Preserve test strength; do not skip, loosen, or delete failing tests without justified approved changes.
4. Inspect CI logs and reproduce locally where feasible; distinguish infrastructure failure from product failure.
5. Report command, environment, exit status, and concise evidence.
6. For UI, include small screens, keyboard/focus, touch targets, RTL and dark mode when relevant.
