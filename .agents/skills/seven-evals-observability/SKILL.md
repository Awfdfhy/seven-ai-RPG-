# Seven Evals and Observability
1. Define observable success metrics tied to user outcomes, not activity counts alone.
2. Use repeatable evaluation scenarios and explicit pass/fail thresholds.
3. Capture minimal structured diagnostics: build/version, operation, duration, outcome, and safe error category.
4. Avoid storing secrets, private story content or unnecessary personal data in logs.
5. Distinguish static inspection, unit tests, browser tests, emulator tests and real-device evidence.
6. Track regressions against baseline and document flaky tests rather than silently ignoring them.
